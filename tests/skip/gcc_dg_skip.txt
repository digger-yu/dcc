# struct-by-value-18(_a) — 已恢复。三个叠加根因都已修好:
#   1) `gen_expr_complex_lit` 对 `long double` 内型无条件把实部重载进值通道,
#      而 LD 的值通道是 x87 st(0) —— 复数字面量每求值一次就永久漏 1 枚 x87
#      栈项, 8 项回绕后 `fstpt` 写 indefinite (0xFFFFC000…) 即 -nan;
#   2) 标量 → `_Complex` 的显式转换 (C99 6.3.1.8p1) 完全没有实现,
#      `checkScld1 (g1sScld1, (Sclcd1)1)` 的 `(Sclcd1)1` 读到从未写过的复数带;
#   3) `gen_complex_ld_materialize` 对标量源的 Cast 走了 `gen_lvalue_addr`
#      捷径 (`Cast => gen_lvalue_addr(inner)`), 把 4 字节 int 变量的地址当
#      32 字节复数对读。
# 回归夹具: tests/integration/c_lang.rs 的
# `complex_ld_literal_keeps_x87_stack_balanced` /
# `scalar_to_complex_cast_converts_components` 与
# tests/integration/c_abi_vararg.rs 的 `complex_ld_struct_by_value_and_va_arg`。

# __thread TLS — 已恢复。旧实现只做了「半套」：符号类型 STT_TLS、.tdata/.tbss 段、
# `pending_tls_rels` 都在，但唯一活跃的产物路径（-c + host ld）对 TLS 符号发的是
# `mov a(%rip)` + R_X86_64_PC32，链接后指向 .tdata **模板**，于是所有线程读写
# 同一份存储、两个线程的 `&a` 相等；实测 tls-test.c 主线程直接读到子线程写入的
# 10。现在 ET_REL 一律走 local-exec 形态（`%fs:` 前缀 + SIB 绝对 disp32 +
# R_X86_64_TPOFF32，取址用 `mov %fs:0` + lea），并补上了聚合 TLS 对象在
# `.tdata` 里的初始化数据（原先 int arr[4] 与 struct S 拿到同一个 offset，
# 互相覆盖）。回归夹具见 tests/integration/c_lang.rs 的
# `thread_local_is_per_thread_and_aggregates_initialized`。

# pr8081 — 已恢复：VLA 作为结构体成员（`char val[size]`）+ 嵌套函数按值返回。
# 三处独立根因：(a) `gen_lvalue_addr` 的 upvar 二次加载编码把 modrm 写成
# mod=00/rm=rbx，紧随的 disp32 被当独立指令执行（嵌套函数读外层 VM struct
# 直接 SIGSEGV）；(b) `AddrOf` 的 Ident 分支缺 upvar 臂，`&b` 落到
# `stack_home_off` 在本帧懒分配同名槽，取到自己的帧；(c) `gen_sret_return`
# 按 `Type::size()` 定长拷贝，VM struct 退化成 8 字节，且运行时求长不能用
# r11 当累加器（`load_upvar` 把 r11 当静态链 scratch）。
# 回归夹具见 tests/integration/c_lang.rs 的
# `nested_function_reads_outer_vla_struct`。
# 已知残留限制（不在本 dg 用例覆盖内）：调用方给 sret 临时缓冲仍按静态
# `ty.size()` 申请（含 16 字节圆整），运行时大小超过 16 字节的 VM struct 返回
# 会溢出该缓冲（`int size = 1000` 的变体 SIGSEGV）—— 需要调用点动态栈分配
# sret 缓冲区才能根治。
